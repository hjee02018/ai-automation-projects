데이터셋 불균형 해결 문제 접근 방안 (마지막 작성자 : 이어진 / 마지막 Update : 2024-09-24 17:12)

배경 :
1. 컴퓨팅 자원의 부족 및 Total Dataset (532GB) 의 학습 대비 기대 성능 불확실성이 존재함
2. 즉, 많이 학습시킨다고 성능이 좋아지는 것이 아님. 설사 그렇다 하더라도 컴퓨팅 자원의 한계로 학습이 불가능함.
3. 이에 학습시킬 데이터셋을 따로 선별하여, 실제 사용하고자 하는 데이터셋의 크기를 줄이기 위함.

상세 상황 설명 :
1. 각 이미지 데이터셋들은 원본 영상에서 특정 프레임이 추출된 구조임. (e.g. 1분 가량의 영상에서 1프레임씩 끊어 총 30장의 이미지를 만드는 방식)
2. 전체 Class 개수는 총 57개이며, 이중 단 한개 밖에 존재하지 않는 SO-05(컨베이어)를 제외하면 실제 학습 가능한 전체 Class 개수는 56개임.
3. 용어 통일을 위해, 같은 영상에서 추출된 이미지의 묶음 일련을 ' Chunk ' 로 정의함
4. 이때 Chunk 를 구분하는 논리적인 방법은, JSON 파일 명의 제일 뒤 언더바 앞 부분이 같을 때 같은 Chunk로 구분 가능함
5. 예를 들어, 'L-210730_B01_A_WS-01_002_0001.JSON' 과 'L-210730_B01_A_WS-01_002_0002.JSON' 은 같은 Chunk 에 속하며, 서로 다른 JSON (혹은 이미지) 파일임.
6. 반대 예로, 'L-210730_B01_A_WS-01_002_0001.JSON' 과 'L-210730_B01_A_WS-01_003_0001.JSON' 은 서로 다른 Chunk 에 속하며, 서로 다른 JSON (혹은 이미지) 파일임.
7. 각 Class 당 필요한 최소 갯수는 500 개로 설정함. 이에 따라 이미지 수는 딱 500장이 될 수도 있고, 더 많아질수도 있음.
8. 많아질 수 있는 이유는 한 Class 에 대한 샘플링을 마치고 다른 Class의 샘플링을 진행시, 샘플링된 이미지에 이미 작업을 완료한 Class 가 이미지 내에 존재할 수 있기 때문임.
9. 특히 WO-01 : 작업자(작업복 착용) - 13.81% / SO-02 : 적재물류(그룹) - 23.76% 등 Total Dataset 에서 그 개수가 많은 Class 는 전체에 고르게 분포할 가능성이 높기 때문임.
10. 통계 출처 : Total Dataset 인 AI HUB 물류창고 작업 안전 데이터 사이트에서 고시한 비율, 실제 다운로드 받은 Total Dataset 과 미세한 차이가 존재할 수 있음.

문제점 :
1. 단순히 For 문을 활용해, 데이터 셋에서 모든 Class 를 각각 순차적으로 이미지를 샘플링 하게 된다면 다음과 같은 문제점이 발생 가능함.
2. 앞쪽에 선택된 Chunk 에서 많은 샘플링 되는 문제점.
3. 이로 인해 뒤쪽에서 선택된 Chunk 에서 적은 샘플링 혹은 아예 샘플링 되지 않는 문제점.
4. 혹은 해당 Class 수가 압도적으로 많은 Chuck 에서 모두 샘플링 되고 나머지 Chunk 에서 전혀 추출되지 않는 문제점.
5. 위와 같은 문제점들이 발생하는 이유는, Chunk 별로 Class 가 균등하게 배치되어있지 않기 때문임.

해결 방안 :
1. 위 문제점으로 인해 Chunk에 편향되지 않는 데이터 샘플링 달성을 위해서는 탐색을 위한 우선순위를 설정해야함.
2. 이에 탐색 우선 순서를 아래와 같이 제시함

샘플링을 위한 탐색 우선 순서 (단계별) :

'Total Dataset의 Class 개수 합'
합의 크기가 작은 Class 부터 선택해 탐색
'Chunk 당 해당 Class 개수 합'
합의 크기가 작은 Chunk 부터 선택해 탐색
해결 방안에 대한 근거와 예상 시나리오 :
1. Total Dataset 에서 개수 합이 적은 Class 를 먼저 탐색해야 본 문서의 <상세 상황 설명 - 4.a> 의 문제를 방지할 수 있음.
2. Chunk 당 해당 Class 개수 합이 작은 Chunk 를 먼저 탐색해야 본 문서의 <문제점 - 1. > 의 문제의 영향을 비교적 덜 받을 수 있음.
